# 蓝厂(vivo/iQOO) LK 通用修补 · 方案说明

> 生成日期：2026-09-05 ｜ 适用镜像：`verified_lk.bin` / `lk_b` / `lk_b.img`（MTK 容器，lk 载荷各异）
> 一句话：**绿厂的打桩思路 + 蓝厂多构建的语义自适应定位 + 对每个被改动镜像的 cert2 做免重签**。

---

## 1. 总体思路

```
原厂镜像
  → [容器识别]  MTK 容器链 (lk/cert1/cert2/bl2_ext/aee/lk_main_/lk_dtbo…)
  → [语义定位]  AArch64 指令语义扫描（不写死偏移），覆盖多套构建
  → [选择性打桩] 尽量"单指令原位改返回值"，不整段替换引导函数头(保结构)
      ├ [1] 伪装回锁 : C(chooser 状态读->0) + E(状态写回判定->1)   (不再整段砍 B)
      ├ [2] 去黄字    : D(橙门 b.ne->b)
      └ [3] 去写保护  : A(csel->mov) + F(UFS门控读->1)
  → [深刷bl2 可选] 定位 bl2_ext 安全校验查询函数(绿厂同款结构) -> 返回0 (默认类别不含; 10888=含, 10887=仅bl2)
  → [免重签(必做)]  对**每个被改动**的镜像(lk、bl2_ext)重算哈希并写/刷新其 cert2 前置块
  → [双自检]        lk 与 bl2_ext 的前置块两槽重算一致 -> 输出
```

- **过验证**：原理见《MTK_LK免重签伪造研究报告》。厂商在 cert2 的私有 OID 槽里存"镜像头哈希 + 载荷哈希"；改载荷后把**内容哈希换成新的**，前面插 90B 前置块（`A0 58` + 头槽 + 内容槽），证书体/cert1 一字不改 → seclib 线性扫 OID 取首值读到伪造槽即通过。
- **为什么必须免重签**：蓝厂校验在 preloader，改载荷不重签就不开机；`10886`(纯免重签)能开机已证明该层被设备接受。
- **为什么借鉴绿厂打桩法**：绿厂验证过"改状态读→0、不砍引导函数、bl2 深刷"能在真机过检开机；但绿厂样本改完没动 cert2 也能开（校验被深刷绕开/该机不查），蓝厂不能省免重签——这是二者的关键差异。

## 2. 语义点与"保结构"做法

| 类别 | 点 | 打桩 | 是否破坏函数结构 |
|---|---|---|---|
| [1] | B chooser | **不打桩**（保留，状态交给 C） | 否 |
| [1] | C 状态装载 | 载荷点 `ldr 全局`→`mov wN,#0`（1 字） | 否 |
| [1] | E 状态写回判定 | 函数**体内** `cset`→`mov wN,#1`（1 字，函数头/帧/读状态/正常返回都保留） | 否 |
| [2] | D 橙门 | `b.ne`→`b`（1 字） | 否 |
| [3] | A 强制参数槽 | `csel`→`mov`（1 字）；部分构建无 A，如实降级仅 F | 否 |
| [3] | F UFS 门控 | `ldr wN,[sp,#i]`→`mov wN,#1`（1 字） | 否 |
| 自动 | bl2 深刷 | 定位 `stp x29,x30,[sp,#-0x10]! + add x29,sp,#0 + bl + bl + and w0,w0,#imm`，把**第 2 个 bl 的安全校验函数**头打成返回 0 | 例外：仍是"查询函数头返回 0"（绿厂同款、其设备已验证）；若要保结构可再挖体内返回点 |

定位核心：
- **chooser 语义锚**：按内容找引用 `androidboot.verifiedbootstate=` 的代码，归并函数 → 唯一含 ≥3 处的函数即状态分发函数 → 定位 C（该函数内第一处"读锁状态全局"）与橙门 D。
- **E 体内点**：`cmp wN,#3; cset/csel; str wN,[xK]` 中的 cset。
- **多构建自适应**：`bti j` 跳转表落地垫不当作函数头（避免 chooser 被切碎）；函数头形态宽容 paciasp/stp预/sub+stp。

## 3. 免重签（cert2）处理与三态

对每个目标镜像节点的 cert1/cert2：

1. **无前置块** → 插 90B 块，cert2 dsize `+0x5A`；
2. **已有本工具块** → **原位刷新**内容哈希（不二次插块、dsize 不变）；
3. 内容槽 = `sha256(改后载荷 [data: cert1头])`，头槽 = `sha256(该镜像 0x200 容器头)`；
4. cert1、原厂证书体、其它节点内容全部原样（仅 +0x90 整体位移）。

入口三态判定：
- **未修补**（cert2 无块）→ 打桩+免重签；
- **本工具修补过/真幂等**（块在、哈希匹配、桩已就位）→ 原样输出；
- **已伪造 cert2 但载荷没补桩**（如 `verified_lk_xingc.bin` / `lk_b.img`）→ **补桩 + 原位刷新**（把这类"只伪造未打桩"补成成品）。

隐藏选项：
- `10886` = **仅免重签，不打任何功能桩**（验证伪造是否被接受 / 纯对照）；
- `10887` = **仅免重签 + bl2 深刷，不打 lk 功能桩**（判断"lk 功能桩"与"bl2 深刷"谁可能导致黑屏：与 10886 对照可拆分）。
- `10888` = **正常类别 + bl2 深刷**（默认类别 1/2/3/全部 **不含 bl2 深刷**，需要时用它显式开启）。

## 4. 界面与批次

- 每文件顺序输出：容器 → 类别/幂等判定 → chooser 锚+各点打桩 → bl2 深刷 → 免重签 → `自检(lk)`/`自检(bl2_ext)` → 输出文件；
- 批次结尾统一 `[批次结果] …` + "免重签=最终必做步骤"说明；
- 语义定位失败时不输出（安全），并明确告知原因。

## 6. img_auth / SBC：为什么没移植成自动打桩

- 绿厂源码注释明确"免授权深刷仅做 bl2 安全校验，**不做 img_auth/SBC 额外打桩**"，那两类在其自身流程就是关闭的历史点；
- 蓝厂镜像里 `img_auth_required` 经查只是被 **printf 打印的日志变量**（verified rel 0xA2214），不是可直接单点旁路的判定函数；
- 结论：**不自动打桩**，避免误伤。若真机仍因"镜像签名认证"拒绝引导自定义内容，应沿"锁/解锁状态 → 是否要求签名"这条判定链处理（与[1]方向直接相关），属下一阶段真机对照项，而不是盲抄 img_auth 打桩。

---

## 7. 真机待验证项

1. 刷新 [1]（C+E 保结构 + bl2 深刷 + 免重签）镜像，确认引导不再卡死/秒重启；
2. 若仍失败，对照 10886(纯免重签) 与各候选镜像（`二分测试镜像/`）二分到具体点；
3. 若指向"镜像签名认证"拒绝，再评估状态判定链（让设备保持可引导修改内容的判定，而非"伪装回锁"）。
